## 背景

ADR-001 将持久层、鉴权、UI 库三项标为「倾向（待首期 spec 最终确认）」。01-tenant-auth 的 tasks 与 design 已按这三项落地（MyBatis-Plus 多租户插件、Sa-Token 鉴权、Element Plus UI），但 proposal 与 AGENTS.md 技术约束表仍写「待定」--同一选型三处口径不一。本 ADR 一次性收口。

## 决策

| 决策点 | 选择 | 备选（放弃原因） | 理由 |
|--------|------|------------------|------|
| 持久层 | **MyBatis-Plus** | Spring Data JPA（复杂查询与框架易打架） | `TenantLineHandler` 单库多租户插件成熟；复杂报表/打印取数手写 SQL 友好；中文企业生态主流 |
| 鉴权 | **Sa-Token** | Spring Security + JWT（重、配置繁琐，无合规审计需求时过度设计） | 轻量、RBAC 开箱即用、注解式鉴权、中文文档好；会话依赖 Redis（docker-compose 已含） |
| UI 库 | **Element Plus** | Naive UI / Ant Design Vue（管理后台场景资料与组件覆盖不及） | 管理后台/表格/表单最主流；Vue3 + TS + Vite 兼容好；按需引入控制体积 |

## 后果

- 00-foundation 引入 Element Plus（前端骨架基座）；MyBatis-Plus / Sa-Token 由 01-tenant-auth 按需引入（实现选型，基座不预置）。
- AGENTS.md 技术约束表三项更新为「已定」。
- 宪法 2.2 / 2.3 不受影响（前后端分离与 API 优先是框架级原则）。
- 未来更换任一项：走新 ADR + `docs/changes/` 提案，必须评估多租户插件与鉴权拦截层的迁移成本。
