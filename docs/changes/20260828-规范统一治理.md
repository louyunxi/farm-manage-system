# 变更提案：规范统一治理（消除双轨漂移与结构冲突）

## 变更类型
修改宪法 / 修改 roadmap / 结构治理（跨域）

## 变更原因
项目审查发现六类规范冲突：
1. **双轨编号割裂**：openspec tasks.md 用 `X.Y` 编号，而宪法/AGENTS.md 的 commit 纪律引用 `T-XX-YYY`；T 编号在权威层不存在，两套编号无映射机制。
2. **M0 双头归属**：roadmap 将 M0 定义为独立里程碑，实际 M0 全部产出物在 01-tenant-auth 的 tasks 1.1~1.7 内（早期 change 名 `m0-foundation-tenant-auth` 的合并遗留）。
3. **域目录三套命名**：中文目录名（docs 层）、英文 change 名（openspec 层）、capability 名，三层靠编号隐性对齐，任一改名即断链。
4. **批量预建 10 个 change 与「逐域推进」流程冲突**：02-10 域 Scenario 数较 roadmap AC 预算缩水 36%~71%，change 长期堆积制造「已建」假象；宪法 5.4 对 change 的定性是「临时，archive 后合并」。
5. **选型矛盾**：01-tenant-auth 的 proposal 写 Sa-Token/MyBatis-Plus「倾向，待 spec 确认」，tasks 已写死；ADR-001 同三项停留在「倾向」；AGENTS.md 技术约束表 Element Plus 仍「待定」。
6. **roadmap 假域**：M3 列出「报表统计、消息通知」两个无域编号的功能域（消息通知实际是 10-ai-agent 的一个任务）。

## 变更内容
1. **M0 拆分**：新建 `openspec/changes/00-foundation`（capability `foundation`，任务 T-00-001~007），01-tenant-auth 摘除基座内容仅保留域 01；roadmap M0 与 00-foundation 一一对应。
2. **编号统一**：任务编号 `T-XX-YYY` 直接写在 openspec tasks.md 条目上（唯一编号源），commit 引用之；`docs/tasks/` 为同步副本。
3. **命名统一**：功能域目录全部用英文 slug（`00-foundation`、`01-tenant-auth`……slug 表登记于 roadmap 功能域总览）；中文仅作显示名（VitePress 侧边栏/表格）。
4. **移除 02-10 九个草稿 change**：需求预算保留于 roadmap（AC 预算列 + 域表格），设计细节在 git 历史（64060e8）可追溯；各域开工时按流程重新 propose；`openspec/changes/` 仅保留活跃 change。
5. **选型固化**：新建 ADR-002，将 MyBatis-Plus、Sa-Token、Element Plus 从「倾向」升级为「已确认」；ADR-001 状态改「已接受」并指向 ADR-002；AGENTS.md 技术约束表同步。
6. **roadmap 修订（v0.3）**：M0 节挂接 00-foundation；M3 功能域收敛为 09/10，「报表统计、消息通知」移入「未立项候选」；「AC 数」列更名「AC 预算」并注明与 spec Scenario 的关系；功能域总览增加 slug 列与 propose 状态列。
7. **同步自动化**：新增 `scripts/sync-openspec-docs.mjs`，将 active change 的 specs/design/tasks 同步为 docs/specs|plans|tasks 副本（自动加 frontmatter）；docs 副本禁止手改；删除 `docs/specs/_template`（openspec propose 是唯一生成器，手写模板构成第二事实源）。
8. **文档同步**：AGENTS.md（目录地图 slug 化、编号规则、技术约束表）、宪法 5.5（任务清单行 + 规则，版本 v1.3）、openspec-tdd-guide（过期行修订 + 本项目编号覆盖说明）、VitePress 侧边栏。
