# 变更提案：宪法集成 OpenSpec

## 变更类型
修改宪法

## 变更原因
项目存在两套并行文档体系：`docs/`（宪法/roadmap/spec/plan/task，AGENTS.md 规定）与 `openspec/`（OpenSpec CLI 的变更/规格/任务，机器校验）。宪法目前不感知 OpenSpec，导致变更流程、规格格式、任务编号三处冲突。需将 OpenSpec 规范写入宪法，确立双源深度融合规则。

## 变更内容
- 5.2 变更流程改为双轨：宪法级/跨域走 `docs/changes/`；域内功能走 `openspec change`。
- 5.3 开发流程映射 OpenSpec 四产物（proposal/specs/design/tasks + apply）。
- 5.4 文档层级双源化：新增「权威事实源」列，纳入 `openspec/` 目录。
- 新增 5.5 OpenSpec 集成：定位、目录映射、四条规则。
- 版本升 v1.1。
- 同步 `openspec/config.yaml` 注入宪法上下文（context）。

## 影响范围
- 受影响：`docs/constitution.md`（五、SDD 约束 + 七、版本）、`openspec/config.yaml`。
- 后续联动：`AGENTS.md` 桥接规则建议后续补；`docs/specs/` 与 `openspec/specs/` 的同步义务。
- 不影响：数据原则、架构原则、术语表本体（仅新增引用）。

## 评审结论
通过 + 用户（项目所有者）+ 2026-08-27 + 备注：用户直接指示「把 openspec 规范写进宪法并深度融合」，本提案作为宪法修改的存档记录，当场执行。
