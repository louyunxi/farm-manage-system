# TDD 工作流

## 触发条件

当用户要求实现某个 Task 或开始编码时，自动执行本流程。

---

## 执行流程

### 第一步：确认前置条件

1. 确认当前 Task 对应的 spec 和 AC 已就绪
2. 确认 plan 中的技术方案已明确
3. 确认 Task 编号（如 `T-01-001`）和关联 AC（如 `AC-01-001`）

### 第二步：TDD 循环（每个 Task 严格执行）

```
┌──────────────────────────────────────────────┐
│  1. 读 AC（验收标准）                           │
│  2. 写失败测试（红 🔴）                          │
│  3. 运行测试，确认失败                           │
│  4. 最小实现（绿 🟢）                            │
│  5. 运行测试，确认通过                           │
│  6. 重构（清理代码，不改行为）                     │
│  7. 运行全量测试，确认无回归                       │
│  8. 对照 AC 逐条勾选自查                         │
│  9. commit: feat(<域编号>): <描述> (T-XX-YYY)   │
└──────────────────────────────────────────────┘
```

### 第三步：输出自查结果

```
Task T-XX-YYY 完成自查：
- AC-XX-YYY: ✅ 通过 — <验证方式>
- AC-XX-YYY: ✅ 通过 — <验证方式>
- 单元测试: ✅ N/N 通过
- Lint: ✅ 通过
- Typecheck: ✅ 通过
```

## 测试规范

### 单元测试（Vitest）

- 测试文件：`*.test.ts` 或 `*.spec.ts`，与源文件同目录
- 测试结构：`describe(模块) > describe(函数) > it(场景)`
- 命名：`it('should <预期行为> when <条件>')`
- 覆盖：每个公共函数至少 **一个正常路径 + 一个异常路径**

### 组件测试（@vue/test-utils + Vitest）

- 测试用户交互行为，不测试内部实现细节
- 每个组件至少 **一个渲染测试 + 一个交互测试**
- 异步操作用 `await` + `nextTick`

### E2E 测试（Playwright）

- 覆盖核心用户流程
- 每个 Feature 至少一个 E2E 场景
- 测试文件放 `tests/e2e/` 目录

---

## 禁止事项

| 禁止 | 说明 |
|------|------|
| ❌ 跳过测试直接写实现 | TDD 铁律：测试先于实现 |
| ❌ 测试和实现一起提交 | 先提交测试，确认 CI 红，再提交实现 |
| ❌ 为了通过测试写假实现 | 实现必须是真实业务逻辑 |
| ❌ 测试覆盖不相关的功能 | 只测当前 Task 的范围 |
| ❌ 测试依赖外部服务 | 用 Mock（MSW / vi.mock） |
| ❌ 跳过重构步骤 | 绿了之后必须清理代码 |
